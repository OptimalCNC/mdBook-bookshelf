# Site Behavior

This document describes the current reader-facing behavior of a built
`mdbook-bookshelf` site.

## Routes

- the directory containing `bookshelf.toml` is the site root
- `/index.html` is the generated documentation index
- every authored markdown page publishes at the same site-root-relative path
  with `.md` changed to `.html`

Examples:

- `index.html` -> `/index.html`
- `docs/index.md` -> `/docs/index.html`
- `docs/architecture.md` -> `/docs/architecture.html`
- `modules/gcode-parser/docs/index.md` ->
  `/modules/gcode-parser/docs/index.html`
- `modules/gcode-parser/docs/reference/modal-groups.md` ->
  `/modules/gcode-parser/docs/reference/modal-groups.html`

## Documentation Index

The site root `index.html` is generated by `mdbook-bookshelf` as a one-page
mdBook. The managed source lives under
`[bookshelf].asset-dir/documentation-index/` as:

- `SUMMARY.md`
- `index.md`

That generated source is rendered by mdBook's normal HTML renderer, so the
site-root page uses the same mdBook chrome, theme, search UI, custom assets,
and live reload behavior as the content books.

It contains:

- one `##` heading per configured category
- one card-style link per categorized book
- optional description text inside each book card
- links from each book card to that book's `<src>/index.html`

Every configured book is a normal categorized book. The generated landing page
is separate from the authored books in the reader-facing model.

## Reading Inside A Book

When a reader opens a content page:

- the sidebar shows only that book's table of contents
- previous and next links stay inside that book
- the page header gets a return button that links to the documentation index
- direct links into nested pages still activate the correct book context

The generated documentation index itself does not show a return button.

## Search

The site keeps mdBook's stock search UI, but the loaded search data is widened
to the whole documentation portal.

Current search behavior:

- each built book still emits its own stock mdBook search assets
- the generated documentation index also emits a stock mdBook search payload
- `mdbook-bookshelf` composes a site-wide shared index at `/searchindex.js`
- each book also gets a localized `bookshelf-searchindex.js`
- `documentation-search.js` switches mdBook's search loader to the localized
  shared index on content pages and to `/searchindex.js` on the generated
  documentation index
- results can open pages in other books
- result labels use mdBook's normal breadcrumb-style search labels, for example
  `G-code Parser » Grammar » Modal Groups » Modal Groups`

In other words, the chrome still feels like mdBook, but search scope is the
entire documentation portal.

Search caveats:

- the generated documentation index and each built content book must contain
  exactly one stock mdBook `searchindex-*.js` file, because those emitted
  payloads are the merge inputs
- those stock payloads must stay compatible with each other so
  `mdbook-bookshelf` can merge and localize the shared search data
- every content book receives its own localized `bookshelf-searchindex.js`
  data file; this is separate from the `documentation-search.js` runtime script
- on a cold load with `?search=`, mdBook may first request the page-local
  per-book `searchindex-*.js`; the documentation runtime then switches future
  search loading to the localized shared index

## Constraints Readers Will Notice

- the site-root entry page is the generated documentation index
- book switching happens through the documentation index or through direct page
  links, not through one merged global sidebar
- the built site keeps source-derived URLs, so `docs/` and other authored path
  segments stay visible in the published routes
